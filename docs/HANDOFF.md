# 馬拉松APP 交接文件：Run-Navigator

Nov 2, 2026 · @ZL

## 目的與背景

把「日月潭 29K」和「京都馬拉松 42K」兩支賽道定位 App 整合成一支 **Run-Navigator**：一套共用引擎，加上多個互相隔離的賽事包，再補上跑步紀錄、自由跑與匯入練習路線。

- **為什麼整合**：兩支 App 有九成程式重複（GPS 對位、語音、通知列、畫面框架），每次改功能都要改兩份。
- **最大的限制**：京都馬拉松 2027/2/21 不能冒險。舊的 `Kyoto-Run` APK 要保留到新 App 通過一次實跑測試才退役。
- **使用者**：新手跑者（日月潭 29K 是第一場長距離），用 Android（Pixel 7／8 Pro），跑步時不看手機，只有停下來才瞄一眼。

## 現況：兩支 App

兩支都已經能用，架構相同：Android 外殼（WebView）載入一份 `index.html` 當畫面，背景前景服務負責 GPS、語音與通知列；GitHub Actions 自動編 APK 並發佈到 Releases。

| --- | --- | --- |
| Repo | [ZLO-25/MSL-run-2026](https://github.com/ZLO-25/MSL-run-2026) | [ZLO-25/Kyoto-Run](https://github.com/ZLO-25/Kyoto-Run) |
| APK | Releases「日月潭29K 最新版」v1.6 | [Releases latest](https://github.com/ZLO-25/Kyoto-Run/releases/tag/latest) v1.0 |
| 套件名稱 | `tw.sml29k.locator` | `tw.kyoto42k.locator` |
| 比賽日 | 2026/11/1 6:35（已完賽） | 2027/2/21 9:00 日本時間 |
| 網頁版 | 原規劃 GitHub Pages（未確認是否已開） | Pages 待開啟（Settings → Pages → Source 選 GitHub Actions） |

**京都版的檔案分工**（整合時以它為基礎，比日月潭版新）：

- `app/src/main/assets/index.html`：畫面、配速計畫、地標／區段／關門／水站資料（`LM`、`SEC`、`CUT`、`AID`、`GELS`）。
- `Route.java`：路線幾何、坡度、GPS 對位（折返段用預期里程分辨去程／回程）。
- `Course.java`：從畫面接收算好的計畫與賽事資料（`Android.setCourse()`），背景服務用同一份。
- `GpsService.java`：前景服務，語音（每 1K、進區段、地標、水站、關門、停下 10 秒）、震動、分段紀錄、每 5 秒更新通知列。
- `Strip.java`：通知列上的「你／計畫／關門線」對照圖。
- `tools/build_route.py`、`tools/build_map.py`：從 GPX 產生路線資料與離線地圖。

**資料流**：畫面算配速計畫 → `setCourse` 存進手機 → 背景服務讀取 → GPS 對位 → 語音、通知列、狀態推回畫面。

## 定案規格

一支 APK、一套引擎、多個賽事包；每場賽事的資料與參數各自獨立，個人偏好全 App 共用，同時只有一場在定位。

**共用與隔離**

| 類別 | 項目 | 範圍 |
| --- | --- | --- |
| 個人偏好 | 語音、震動、每 1K 報告、停下 10 秒報告、亮暗主題、跑者名稱 | 全 App 共用 |
| 賽事參數 | 目標時間、預估起跑延遲、起跑時間、分段紀錄 | 每場各自 |
| 定位 | 背景 GPS 服務 | 同時只有一場；開始新的一場前先請使用者停止另一場 |
| 發版保護 | GitHub Actions 每次編譯前，用示範模式把每場賽事都跑一遍 | 任一場出錯就不發佈 |

**使用者的決定（2026/11/2 討論）**

1. 日月潭：回顧紀錄＋明年再跑＋當練習路線，全部都要。
2. 新賽事：要能自己匯入賽事包（GPX＋賽事設定檔）。
3. 不互相影響：分段紀錄、每場設定、程式更新、比賽日不誤開，四項都要。
4. 打開 App：每次先出現賽事／路線清單，手動選。
5. 設定：個人偏好共用、賽事參數各自獨立（上表）。
6. 舊 APK：三支並存，新 App 套件名稱不同，不會蓋掉舊的；確定沒問題再刪。
7. 練習：要「自由跑」（無路線，只報距離與配速），也要從 Google My Maps（KML）或其他含座標與高度的 GPX 匯入練習路線。
8. 網頁版：只做測試與分享，比賽一律用 APK。

**新功能**

- **完賽判定**：進入終點 100 m 內、且已跑 98% 以上距離 → 自動完賽；另有「我完賽了」手動按鈕，判定錯可取消。完賽後停止偏離提醒與語音，顯示成績頁。起因：日月潭當天到終點休息時，App 仍一直報「不在賽道上」。
- **紀錄**：每次跑步（賽事、路線練習、自由跑）存一筆：日期、路線、淨時間、各分段、配速曲線、GPS 軌跡，可回看、匯出 GPX、複製分段；可匯入舊日月潭 App 的分段紀錄。
- **匯入路線**：選檔（KML／GPX）→ 預覽（距離、爬升、有無高度）→ 命名與區段切法（依坡度自動切／每 1K／用 My Maps 標記點）。沒有高度資料也能用，只是不畫坡度。

## 已知問題與注意事項

| 項目 | 說明 | 處理 |
| --- | --- | --- |
| 終點附近誤報偏離 | 日月潭當天到終點休息仍報「不在賽道上」 | M1 完賽判定 |
| 折返段對位 | 京都北山通、丸太町、今出川都是折返，去程回程只隔一條馬路 | 已用「預期里程」加權解決，新引擎要保留這個邏輯與測試 |
| 京都前 12.5K 關門最緊 | 6.1→9.1K 上坡卻要求 7:40/km；目標 5:30＋延遲 15 分時，前 6.1K 計畫排到約 7:00/km | 配速計畫的關門保護：前三關留 4 分、之後 6 分；目標＋延遲 > 5:54 時只警告不保護 |
| 練習時的關門時間 | 不在比賽日時，關門以「已跑＋預估起跑延遲」計算，否則永遠顯示已超時 | 新引擎沿用 |
| 本機無法編 Android | 工作環境下載不到 Android SDK，只能用替身類別做語法檢查 | 一律靠 GitHub Actions 編譯，看 Actions 結果確認 |
| 建 repo 與改設定 | Claude 沒有建立 GitHub repo、開 Pages 的權限 | 使用者先建空 repo（Public、不勾 README），Pages 由使用者在 Settings 開 |
| 語音念法 | 「10:02」與括號地名念起來怪 | 念之前轉成「10點02分」、去括號（已實作） |
| 示範模式的分段 | 示範 1 秒＝1 分鐘，地標分段會有約 1 分鐘誤差 | 只影響示範，實際 GPS 每秒更新無此問題 |

比賽相關的硬規則：比賽日只用 APK；網頁版鎖屏後瀏覽器會停，不能拿來比賽。

## 新增賽事：只要說「新增 XXX」

以後要加一場比賽，在專案裡只打「新增 XXX」（例如「新增 2027 臺北馬拉松」）。下面這段規則貼進專案指示後，Claude 會自己查資料、補齊所有要留意的地方，只有真的需要你決定的事才會問。

```markdown
## 新增賽事規則（Run-Navigator）
當我只說「新增 XXX」（XXX＝賽事名稱，可能含年份或距離），照下面流程做，不要等我補充細節。

### 1. 先自己查（官方優先，再用真實跑者紀錄多方比對，每項標來源與可信度）
- 日期、鳴槍時間、時區、距離組別、起點／終點、總時限
- 接下來幾年（至少 3 屆）的報名期間與比賽日期：已公布的附官方來源；沒公布的照往年慣例推估並標「預估」、寫推估依據（寫進 race.json 的 schedule）
- 關門點：名稱、公里數、關門時刻（以鳴槍計還是個人計）
- 補給站：水／運動飲料／食物／鹽的公里數與品項；廁所
- 路線檔：官方 GPX > RideWithGPS／Strava／Garmin／ibuki 等公開路線；找不到就請我提供（My Maps KML 或 GPX）
- 地形：每段爬升與下降、最高點、陡坡、未鋪裝或狹窄路段、風大路段
- 路線結構：折返段（去回程只隔一條路）、繞圈（同一段跑兩次以上）、多組別共用路段與分岔口（例：日月潭 29K 在頭社右轉、42K 左轉）
- 起跑：分區、整隊截止、各區過線延遲實測、配速員時間與分區
- 規則：是否禁止耳機或手機（影響語音提醒的用法）、寄物、退賽交通
- 天氣：近 3 年比賽日起跑與終點氣溫、降雨
- 報到時間地點、要帶的證件；海外賽要注意現金、時差、手機漫遊

### 2. 只問我這些（一次問完，用選項）
- 報哪個距離組別（有多組時）
- 目標完賽時間；不確定就依我最近一場成績換算建議
- 起跑分區（不知道就用預估延遲，之後可改）
- 查不到路線檔時，請我提供檔案
- 資料互相矛盾、會影響配速或關門判斷的地方

### 3. 做成賽事包（不能影響其他賽事）
- 新的賽事包：獨立 id、獨立儲存（參數、起跑時間、分段紀錄）
- 路線縮放到官方距離，與官方地標比對誤差（目標 ±0.3 km 內，超過要說明）
- 地標、區段（A 點→B 點、地形、策略）、關門、水站、能量膠計畫、關門保護後的配速計畫
- 離線地圖、語音念法（時間念成「幾點幾分」、去掉括號）
- 折返或繞圈路段：確認 GPS 對位不會跳到另一條腿，並用示範模式驗證
- 時區以賽事當地為準，畫面標明

### 4. 驗證與發佈
- 示範模式跑完新賽事全程：無錯誤、每 1K 與地標語音正確、關門餘裕合理、終點自動完賽
- 既有賽事包全部重跑一次，確認沒被影響
- 版本號 +1、推上 GitHub、確認 Actions 編譯成功
- 官方參賽指南還沒公布的話，設排程在賽前定期檢查並自動更新

### 5. 回報我
- 一張表：查到的資料、來源、可信度、還缺什麼
- 這場最需要注意的 3 件事（例：前段關門最緊、某處分岔口、禁止耳機）
- APK 下載連結，以及手機上要確認的設定
```
